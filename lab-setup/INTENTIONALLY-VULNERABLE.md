# Intentionally Vulnerable Settings — and Their Fixes

This lab only teaches something if specific weaknesses exist **on purpose**. Each one below is created by the setup scripts, is required for the matching attack playbook, and is paired with the production fix applied in `hardening/`. **None of these settings should ever exist outside this isolated lab.**

| # | Vulnerable setting (in this lab) | Enables attack | Production fix |
|---|---|---|---|
| 1 | `svc_sql` service account has an SPN set and a **short human password** (`LabSvc!2026` / CHANGE_ME in your build) with **RC4 allowed** (`msDS-SupportedEncryptionTypes` unset) | Kerberoasting: request the TGS, get an RC4 (`0x17`) ticket, crack offline (hashcat 13100) | Use a **gMSA** (managed, 240-char, auto-rotated) or a 25+ character random password; set account to **AES128/AES256 only**; alert on 4769 + `0x17` |
| 2 | A standard user (`j.rodriguez`) is used interactively on WS01 where a **Domain Admin has previously logged on**, leaving reusable credential material in memory (LSASS) in the *unhardened* baseline | Credential theft → Pass-the-Hash lateral movement | **Tiered administration**: Domain Admins never log on to workstations; **Credential Guard**; separate admin accounts per tier; LAPS for local admins |
| 3 | **SMB signing not required** and **LDAP signing / channel binding not enforced** on DC01 in the baseline | Relay and tampering opportunities; weaker lateral-movement resistance | Require SMB signing; enforce LDAP signing + EPA/channel binding via GPO |
| 4 | Advanced audit policy starts minimal on a fresh DC promote; this lab then enables it via `Enable-Auditing.ps1` — if you skip that script you are "blind," which is itself the lesson of Phase 0 | Attacks succeed silently (no 4769/4662/4648 evidence to detect) | Enable the audit subcategories in `Enable-Auditing.ps1` + Sysmon + PowerShell Script Block Logging (4104) on DCs and workstations |
| 5 | Domain Admin membership is **standing** (always on) for `a.cedillo-admin` instead of just-in-time | Any DA credential theft = instant domain compromise, incl. DCSync rights | Just-in-time elevation (PAM/JIT group membership with TTL), replication rights restricted to DC computer accounts only, alert on 4662 with replication GUIDs from non-DCs |
| 6 | **Unconstrained delegation: NOT enabled in this lab.** It is documented here only to say so explicitly — enabling it is unnecessary for the attack chain and adds risk if the lab is ever mis-networked | (If it were on: coerce + capture TGTs on a compromised server) | Prefer **constrained / resource-based constrained delegation** only where required; mark sensitive accounts "Account is sensitive and cannot be delegated" |
| 7 | krbtgt has **never been rotated** since forest creation (true of most fresh labs) | Golden Ticket persistence would survive a single password reset of user accounts | Rotate krbtgt **twice** (double reset, waiting for replication + ticket lifetime between resets) on a schedule and after any suspected domain compromise |

> Rule of the lab: every item above must be *fixable by running `hardening/`* and re-testing. If an attack still works after hardening, the write-up in `findings/` has to say why — that's the difference between a demo and detection engineering.
